# Q3 开发标签核验执行补充：#86（抽样前冻结）

本轮只生成 MOT20-01/02 的双人独立核验材料，不读取或填写任何人的答案，不据此宣布标签正确或资源通过。#86 授权材料制作；第二核验人的落实和两份独立提交仍须人类完成。

## 1. 绑定、范围和先例

基础协议 `docs/label_qc_protocol_v1.md` SHA256 `77439ad9f601fa5bb591dd5a757fc3cae3487888e0ad350ddd77add46dc5fdb6`；v2 `docs/label_qc_protocol_v2_78d.md` SHA256 `581279bfd8445f15236caea64bf3da25afd45f376c8c8e007d5584c94d3b90f1`。原文不改。本补充明确执行字段、随机 API、Q2 排除和统计解释，不改派生标签或系统规则。

沿用上述协议已核查的 MOT16/MOT20 标签语义与 PETS2006 人工核验先例。Cohen's κ 是描述两人超出边际偶合的一致性工具；这次不提出新的指标，也不将人工核验称为方法创新。

母体只取 `release/mot20_crossing_events_v0/labels/` 的 transitions、lineage、geometry、summary，核对包 MANIFEST 内哈希。原始公开 GT 仅用指定 01/02 目标种子帧的定位；原图仅从这两段读取。禁止读样例系统输出、评分、Q2 答案和浏览器存储、测试数据或封存结果。Q2 抽样清单只投影 `items[*].gt_event_id`，不使用分组或任何系统表现字段。所有读取记路径、字节数、SHA256、用途；图片另列帧谱系。

## 2. 抽样和缺额规则

采用 v2 概率配额，每序列可见度四档顺序 `low, mid_low, mid_high, high`，配额 `3,2,2,2`；只有 01/02，最多 18 个已确认事件。未确认转换各序列最多 2 个（总计4）；无确认事件窗口各序列最多2个（总计4）。#86 明确禁止按系统结果选样，所以 v2 的定向 U 槽本轮不执行，也不将这些名额转给概率抽检。其他数据集/测试的名额保持未执行。

排除 Q2 已选入事件的精确 event_id。先验证它们均在发布包的01/02转换表中且唯一，再在形成概率母体前排除。不以 Q2 的组别、答案或系统表现筛选。相同人物在不同门上的其他事件依原协议保留；本轮不能声称核验人从未看过同一时段，开始前记录既有接触情况。排除后的概率母体不代表全体标签，不能把其误差率外推到被排除的 Q2 样本。

确认/未确认的稳定排序键为 `(dataset, sequence, gate_id, reference_id, target_frame, direction)`，未确认再加 `transition_id`。映射分别为常量MOT20、`sequence`、`line_id`、`track_id`（整数）、`gt_frame_1based`（GT 1基整数）、`direction`（字符串）；transition_id 用冻结 `event_id`。缺键、重复键、未知可见度或序列越界即停，不猜补。可见度取 `attributes.visibility_bin`，四档名和顺序如上，语义不另分档。最后来源区支持帧取 `audit.source_support.gt_frame_1based`，须与冻结转换第一个endpoint及lineage支持区间首帧一致。

按01、02及四档原顺序遍历，分别使用 `random.Random(20261027)`（确认）、`random.Random(20261030)`（未确认）、`random.Random(20261031)`（无事件窗口）。每非空层调用 `rng.sample(sorted_pool, min(quota,N))`；空层不调用。短缺全部抽取，不跨层补齐。此 API 选择在首次抽样前固定，保存 Python 版本和脚本哈希。

无事件窗口严格用 release `labels/summary.json` 内的既有核心 `windows` 清单，区间0基半开、时长≤20s，与同序列每条冻结门组成 gate-window。该门两个方向均无 confirmed=true 且 target_frame−1 位于窗口内，才属候选。只使用这份既有清单，不新增步长或裁短长窗口。保存所有候选/排除理由和缺额。三个母体分开，不能把未确认或无事件检查混入确认标签错误率。

每层保存排除前N、Q2排除数、最终N、抽到n、纳入概率n/N、设计权重N/n。同人多门相关性保留。每条展示使用匿名编号；编号先按类别抽取次序赋值，随后两人分别用20261028、20261029对同一批编号shuffle。代号Q3A/Q3B仅隔离本地保存，不是身份认证，必须使用不同设备或浏览器个人资料，独立提交前不交流样本答案。

## 3. 展示、答案与时间

确认和未确认转换使用相同页面格式，不透露类别、可见度、预期方向或预期时刻。默认目标进入区帧前后各2秒；支持扩展至前后各5秒。具体区间为0基半开 `[max(0,target_frame−1−r), min(L,target_frame−1+r+1))`，r=50或125帧。边缘裁至原序列，不补帧。无事件窗口完整显示批准单元。

视频只显示原图、该门冻结口线与两侧区域轮廓（A、B），不显示目标轨迹或系统输出。第一遍完整看过默认片段后，才可打开固定最后来源区支持帧的“待核参考”静态框图；不画整段GT轨迹。该提示来自估计身体框，不是身份/过线真实性的证明。固定种子帧不在扩展许可范围、GT行缺失或提示无法形成时，保留条目并记 `reference_target_not_locatable`，不换清楚的帧；未定位不冒充视觉不确定。

目标条目回答：穿越支持/反对/不确定；A→B/B→A/不确定；两侧身份支持/反对/不确定；时刻可定/不可定/不确定；可选最早/最晚帧和支持帧；问题类型及既有接触。标签时间语义是从一侧移动后首次进入另一侧区域的观测时刻，不是穿过中间数学直线的精确时刻；说明页区分两者，人类时间区间按进入另一侧区域来回答，看不出脚点就保留不确定。无事件窗口回答是否观察到候选/无法穷尽，并可记候选方向、时间区间与位置描述；不要求背书无人越线。答案均无默认选项。

每条60秒，包括加载、观看、提示和填写；达到预算冻结该轮回答，记录 `uncertain_time_budget`，未完整观看另记 `incomplete_view`，不自动填视觉答案。独立阶段最多120分钟。未打开记not_reviewed；技术失败单列。本批至多26条，按每条30–60秒估计13–26分钟，连说明/合成练习15、检查10、讨论20、缓冲15，总计划73–86分钟/人，仍受180分钟总上限约束。实际条数不足时据最终清单重新列计划值。前12个正式随机条目只记录实际速度，不改变抽样。第二人尚未落实，不宣称两人核验完成。

## 4. 一致性指标和事先写定的解读

本轮只写统计规格，不读取任何回答或计算这些统计。日后两份独立提交锁定、由负责人批准分析后，按以下规则执行：

1. 各层列N、n_draw、A/B实际完成、共同有效n_pair、视觉不确定、提示不可定位、技术失败、超时未看完、未打开。不得用完成数量替换抽样概率。所有抽中条目在最终账本中保留。
2. 对穿越、方向、身份分别列3×3表。双方完整观看且无技术/定位阻断才进入该字段配对分母；视觉“不确定”仍是第三类。原始一致率p_o=对角线总数/n_pair；p_e=各类两人边际频率乘积之和；κ=(p_o−p_e)/(1−p_e)，分母为0记NA。时间可定问题同样三类报告。κ只作描述，不以惯例阈值宣称标签正确；两人都不确定不算标签通过。
3. 时间区间报告双方有有效区间的分母、闭区间相交比例、区间宽度（帧和秒）；只有双方区间宽为0时才报点时差。禁止将缺失区间当0误差。
4. 独立判断与裁决分开保存。任何一人反对已确认事件的穿越/身份/方向，或候选支持时段与派生时刻不兼容，均进关键争议表，由人类裁决，不自动修改标签。不确定不能自动当错误或正确。
5. 裁决后对确认概率样本给“错误比例的识别范围”，不是置信区间：每层明确错误数e、仍不能判定数u（含未核验和技术阻断）、抽中n，则 `[e/n,(e+u)/n]`；完整概率母体的设计加权描述用层权重N_h/ΣN_h加权该区间。未覆盖层不估计总体；重复人物/序列相关性不假装独立。该范围只量化抽样条目当前已知/未知，不能解释为总体误差95%上限。未确认转换和无事件窗口各自只报告计数与线索。
6. 发布解读规则：只要存在未解决的关键身份/穿越争议，就不能称该条目“人工验证通过”；只要确认任何系统性派生错误，就暂停相关资源视图/确认表，提出版本化修复后经审查重建。若仅视觉不可判，原标签保留但标uncertain，论文限制声明。只有全部抽中条目都有两份独立状态记录并完成争议处置流程，才可称本批QC流程完成；这仍不证明整个资源无错。不得因错误比例或κ不好而换样本/阈值，或把未知删去提高一致性。
