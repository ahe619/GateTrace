# A2：派生过线标签的双人独立核验协议 v1

结论：拟议核验最多120个条目、每人最多3小时，用于发现派生事件的存在、方向、身份与时间支持问题；它不能证明整个资源没有漏标，不能把“看不清”改成确认正确。当前仅交设计，未抽样、未读新标注、未渲染、未指定已到岗的第二名核验人；需要Claude审查和用户落实人选后另行执行。

版本日期：2026-10-23。范围与限制沿用 #77、#77a、#78、#77e。当前可操作的数据仍仅为已授权开发输入；文中测试/外部序列是未来工作规格，本文件不授权读取它们。体育场e18的弱任务标注另见A4，不以本次公开资源抽检代替e18标注。

## 1. 核验对象及已有工作的边界

核验的是由原始标注和冻结几何派生出来的过线条目，而不是重新标完整视频。原始MOT轨迹本身是参考，不是天然无误的视觉身份答案；框的遮挡部分可能经过估计，派生时间也可能受到插值和区域确认规则影响。MOT16原文§II-B/C/E/F说明了全身框、遮挡、身份中断和质检口径；MOT20§II沿用其标注协议。两篇原文已于2026-10-23核查，见[1–2]。这正是独立视觉核验和保留不确定项的原因。

PETS2006已有事件对齐检查暴露GT错误的先例；沿用其核验思想，不宣称“发现GT错误”是新方法。来源阅读深度与链接见 `docs/resource_spec_v2.md`：Claude已核原论文§4–5，Codex不把自己的索引核查冒称全文重读。我们的待交付增量是每次核验的支持帧、独立判断、版本和后续更正可追溯，而非两人复核本身的新颖性。

本协议不使用系统报警、系统漏报、匹配成败或E1类别来挑选核验条目。E1的机制检查如需人眼证据，应另设定向诊断清单，不混入这里的概率抽检估计。

## 2. 抽检母体与最多120条的预算

母体清单在抽样前另行冻结：数据集/序列、源文件哈希、允许范围、几何版本、派生代码、确认与未确认转换、可见度及其来源。所有几何无效、插值、未知可见度等排除项单独列数；不得先删掉“难核”的人。没有相应许可或测试开封授权的序列保持未执行。

### 2.1 已确认派生事件：最多96条

|任务|计划分配|条数上限|分档定义|
|---|---|---:|---|
|MOT20身体过线|01/02/03/05，每序列四个冻结可见度档，各3条|48|沿用原MOT20门槛协议的事件分档，不重新选分界|
|MOT17身体过线|02/04/09，每序列四档，各2条|24|沿用审定后的MOT17派生定义；无效线不得回填|
|HT21人头过线|03/04，每序列12条|24|独立的人头任务，按有效线和方向做比例分配；不伪造身体可见度四档|

HT21的人头锚点、区域和标志语义必须先在A4后续协议中冻结，才可形成母体；否则全部28条（24条已确认事件及下述4条反向检查）保留为待执行，不用其他数据顶替。MOT17实跑或测试序列的未授权状态同理。

每个可见度层内先按稳定键 `(dataset, sequence, gate_id, reference_id, target_frame, direction)` 排序，随后用标准库 `random.Random(20261027)` 顺序无放回抽取。遍历顺序固定为上表、序列升序、原协议可见度档顺序。HT21按有效线ID、方向的字典序分配12个名额：先按母体量比例取下整，再按小数余数从大到小补足，同余按字典序；层内同样无放回。母体不足则全部抽取并报告缺额，不改档、不跨序列补齐、不挑易读样本。

未知可见度不塞进最低档。若冻结母体存在未被上述四档覆盖的条目，先报告其数量及成因；在实际抽样前另写补充方案审核。不得看核验结果后补一个“未知层”。

同一人可能跨多条线，抽样键保留这些事件，不事后去重换人。记录其共同的参考身份/源视频组，公开条目数和独立身份数；不能把96条当作96个独立人或独立场景。

### 2.2 两类反向检查：各最多12条

另从冻结GT派生母体抽取：

- 12条“有区域转换、但未达到派生确认条件”的候选，检查确认条件是否排除了视觉上可支持的穿越。
- 12个“该线的评估窗口内没有派生确认事件”的窗口，检查是否存在可能的漏派生。窗口使用各数据集已批准的评估单元，不另看系统输出切窗。

每一类名额相同：MOT20-01/02/03/05分别2/2/1/1，MOT17-02/04/09分别2/1/1，HT21-03/04各1。候选不足则缺额，不转移名额。先稳定排序，再分别用种子20261030、20261031抽样；不与2.1共享随机状态。无事件窗口之间若重叠，按其原评估单元保留并记录，不声称独立。

两类反向检查的可执行母体须先输出、记哈希：未确认转换键为 `(dataset, sequence, gate_id, reference_id, target_frame, direction, transition_id)`，注明未确认的冻结理由；无事件窗口键为 `(dataset, sequence, gate_id, start_frame, end_frame, window_id)`，区间使用0基半开 `[start_frame,end_frame)`。后者“无事件”指该线两个方向都没有派生确认事件，不是某个目标没有过线。只允许从已经批准的核心评估窗口清单读取区间，不新设步长、不由人临时切片、不看系统输出。若该数据集没有唯一、已冻结、时长不超过20秒的核心窗口清单，本类暂停，先审定该清单；不能把更长窗口临时切短而改变抽样母体。报告完整的保留/排除理由。此缺件阻断不意味着已核验“没有事件”。

三种母体分开报告。12个无事件窗口只是遗漏线索检查，不足以估计全资源召回率；未确认转换中的核验结果也不能与已确认事件合并成一个“标签准确率”。

## 3. 让核验人实际回答什么

每个已确认/未确认转换条目回答：

1. 是否有该目标穿越指定几何边界：支持 / 反对 / 无法判断。
2. 方向：两个规定方向 / 无法判断。先说明虚拟口线的任务语义，不把体育场真实出口语义搬到公开视频。
3. 是否能在两侧确认是同一人：支持 / 反对 / 无法判断。只因原GT的ID一致不能选“支持”。
4. 可支持的穿越时刻区间 `[最早帧, 最晚帧]`；看不到准确时刻时可以给区间，不能强迫填一个点。
5. 支持帧和问题类型：遮挡、出画、估计框底、疑似ID变化、几何/派生不符、时间无法定、证据不足、超时等。

对没有派生事件的窗口，只先回答“是否观察到候选穿越/无法穷尽”，再记录发现的候选及支持区间。不让核验人背书“肯定无人越线”。

核验页面只显示原始视频与冻结几何。目标定位提示可在第一遍观看后手动打开，提示来自原参考框，明确标“待核参考”；不显示系统输出、算法名称、报警、可见度层、预计方向/时刻或另一人的答案。目标种子帧固定为派生条目的最后来源区支持帧；若该帧目标不可辨，记录无法确认，不自动挑“更清楚”的人。

默认提供事件前后各2秒（无事件窗口提供整个批准单元），允许在原许可范围内扩展到前后各5秒。任何身份需要更长上下文才能判断的条目记为“当前证据不足”，进入后续人工裁决请求；不能凭短片强行定同人。记录实际展示范围及任何提示操作。页面仅在相应开发/确认数据读取获准后生成；本文件没有渲染授权。

## 4. 双人独立与分歧处理

两名实际人类核验人：用户与尚待确定的第二人。二者分别收到不同随机顺序（种子20261028、20261029），独立提交，在两份原始提交锁定前不见对方答案、不讨论具体样本。AI不能充当第二名核验人，也不能把Claude/Codex代码复算称作人类身份核验。

保留两份不可覆盖的原始提交。独立阶段结束后才作分歧讨论，并另存裁决记录：原判断、依据、补看范围、是否达成共识、仍未解决的内容。原参考标签、独立判断和裁决视图分别版本化；不手工覆盖原派生表，不用新的裁决回填到已完成的T3等旧结果。

两人一致“无法判断”仍然是不确定；两人一致“支持”也不是逻辑上的绝对真值。系统主结果使用哪个标签视图、如何处理不确定和参考争议，须在确认执行前写定；至少并列原始参考视图与审计状态，报告分母变化，不能静默排除难例后提高指标。

## 5. 时间预算与未完成规则

每人上限180分钟（估计，不是实测）：说明及合成练习15分钟，首次独立核验120分钟，独立提交及检查10分钟，锁定后的分歧处理20分钟，缓冲15分钟。三类条目均设单条60秒硬上限，从打开条目开始到提交为止，含加载、观看、填写；技术加载失败另记，不强迫猜测。首次阶段120分钟、裁决阶段20分钟分别硬停止，不能靠挪用裁决时间隐去独立阶段的超时。自动播放时间不等于人工耗时。

正式清单中的前12条用于记录实际速度，不换成容易的练习条目、不看正确率后改样本。达到单条预算仍不清楚时记 `uncertain_time_budget` 并提交，不用猜测保持进度。未看完要求片段时还记 `incomplete_view` 和实际观看帧范围；这不算一次完整的“未发现穿越”。若总预算不足，尚未打开的条目记 `not_reviewed`；裁决未完成保持 `unresolved_adjudication`。保留原抽样概率，不得拿完成部分冒充全量随机样本的无偏估计。以后补时需单列轮次。

完成数量可能少于120，这是诚实的工作量限制。高遮挡事件的人工可判定性本身是本资源需要公开的属性，不能靠延长、换人或删样本把它藏掉。

## 6. 预定统计与能够支持的结论

执行后先报告每层母体N、抽到 `n_draw`、两人实际提交 `n_review_A/B`、双方有效提交的 `n_pair`、未核验及不确定数。层内简单随机抽样的 inclusion probability始终为 `n_draw/N`、设计权重为 `N/n_draw`，不能用完成数量替换抽到数量；HT21用其线×方向层。层为空或 `n_draw=0` 不估计该层质量。不能把均匀分档抽样的未加权平均当总体标签错误率。共同完成子集若有非随机缺失，即使带原设计权重也不宣称是总体质量的无偏估计。

逐字段仅在双方有效提交的共同条目上给三类混淆表与原始一致率，另给Cohen κ作为描述（观测一致率p_o、边际期望p_e，κ=(p_o−p_e)/(1−p_e)；p_e=1记NA），同时报告未配对缺失。`not_reviewed`、技术失败和观看未完成不是视觉“不确定”；完整观看后仍无法判断才进入三类表的不确定类。超时但已经完整观看的条目可以提交不确定；超时且未看完则按未完整核验处理。不确定不能先剔除再报高一致性。时间区间报告重叠比例及宽度，点时间差仅对双方都给出确定点的条目列示。方向项的有效分母写明。

每层仅2–3条、各序列相关、同人多线重复，本设计不足以给出精确的分层误差率或笼统“95%可靠”的承诺。主报告完整计数、权重、重复组和个案，不默认二项独立置信区间。两人标签一致率不是派生标签准确率；未核验全视频也不能推断完整召回。

任何确认穿越被反对或身份被反对，保留事件键与证据，列为关键争议；不自行降权、删除或修正全体。若争议揭示系统性派生错误，停止相应确认表，先提出有版本号的修复、重建范围与复算方案。若只是无法视觉核实，限制论文能主张的证据层级，不把未知称为错误。

## 7. 实际执行的入口条件与交付

- 10/27前必须落实两名核验人的姓名/角色、时间，以及可以合法提供给他们的材料；没有人力不能称作成熟基准的双人核验。
- 抽样前冻结母体、任务定义、许可/权限、协议哈希、页面版本与读取清单。HT21任务未定义或测试未获授权时不读取、不抽取。
- 测试片段核验另需明确授权；在核验人看到片段/判断前先锁定待确认系统、派生规则、评分及分析版本。核验结果由指定核验/裁决负责人保管，向方法开发方只提供执行状态和是否存在阻断，直到批准开封；不能反馈用于改待确认系统、阈值或挑选样本。发现参考错误只能进入有版本号的修复与复算审批，原版本与全部条目保留。
- 输出未来位于独立的QC新目录：样本清单及概率、渲染源帧谱系、两份独立提交、分歧与裁决、每层汇总、读取与运行记录。源视频不随标签包再分发。
- 11/6前关键身份/派生争议和复现缺口仍未解决，则缩小资源声明或不包装成成熟基准；不能用删除争议样本来通过关口。

本版没有生成任何样本或人工答案，也没有替代Claude的审核。下一步是审核本设计、确定人员和确认数据边界，不是直接读取测试数据。

交付前静态修订：Codex内部子代理指出反向母体、计时、缺失分母及测试核验先后四处需明确，本版已补齐；这是内部文档检查，不是Claude批准或第二位人类核验。初稿在本轮内修订，未执行抽样或看新数据。
