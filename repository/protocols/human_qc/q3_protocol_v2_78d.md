## 1. 修改依据及预算

#78b/#78d要求抽样覆盖E1的U类，但U是系统条件下的自动证据不足分类，不能当作参考标签错误；也不能把这类定向样本混入总体标签质量的概率估计。v1 §1最后一段改为：**概率抽检不按系统输出选择；另设定向U核验层，仅检查相同参考事件是否得到人眼支持，独立报告。**

|部分|本增补上限|与v1的变化|
|---|---:|---|
|已确认派生事件的概率抽检|84|MOT20每序列由12减为9，其他不变|
|未确认转换的反向检查|12|保持v1母体、种子及缺额规则|
|无确认事件窗口的遗漏线索检查|12|保持v1母体、种子及缺额规则|
|E1 U类的定向核验|12|新增，仅MOT20-01/02|
|最多展示条目|120|合并重复条目后可以少于120，不补易例|

以上均为拟议配额，**不是已抽到的事件数**。84条概率抽检中，MOT20-01/02/03/05每序列四档的配额依原档顺序为 `3,2,2,2`（低档3，其余各2），共36；MOT17仍24，HT21仍24。随机排序、种子20261027、层内无放回、未知层暂停及无授权不抽取等规则继承v1。原种子不变不代表原抽样结果存在：两版至今均未执行。

减少概率样本以满足时间上限是设计阶段的资源取舍，不按任何人工核验结果调整。MOT20层内纳入概率仍为实际抽到数量/母体数量；不能沿用v1的3条配额权重。未获授权的测试、外部数据名额保持未执行，不转给开发集凑满。

## 2. U清单如何形成，怎样保证可复现

未来执行只读取已获准的E1开发输出，不重新归类、不重新评分。先冻结E1 v2输出文件及哈希、字段字典和以下抽样实现。U母体是MOT20-01/02全部已确认参考事件在P1/P2/v11/O1/O2中的现有U记录；没有U记录的事件不人为加入。正式抽样前须确认E1独立复算状态，若输出改版，先更正绑定并审查，不能悄悄混版。

每个序列设六个固定槽，每槽最多1条，顺序为：

1. `U_SIDE_REFERENCE`
2. `U_GEOMETRY`
3. `U_DETECTION_COMPETITION`
4. `U_IDENTITY`
5. `U_ONE_SIDED_DETECTION`
6. `U_MIXED_TRACK`

系统代码只是形成定向清单的工具，页面不显示。每个“序列×U代码”槽的候选记录按 `(system, gate_id, reference_id, target_frame, direction)` 排序，MOT20-01先于02，使用独立 `random.Random(20261032)` 顺序抽一条；空槽记缺额，不跨类或跨序列补齐。稳定键对应的具体字段名必须在清单冻结时验证，缺键则停止，不猜字段或从人工答案补齐。不得从某槽挑“最有说服力”的案例。

实现口径进一步固定：同一U随机实例对每个非空槽调用一次 `rng.choice(sorted_candidates)`，空槽不调用随机函数；不能改用shuffle或sample得到另一份清单。排序中的system、gate_id、reference_id、direction按输入模式声明的字符串字典序，target_frame按整数；不得把帧号转字符串排序，也不把字符型事件键猜成人物ID。实际字段映射、类型和重复键检查必须在抽样实现冻结时验证，并保存Python版本、脚本哈希及纯合成重放记录。这里尚未读取抽样母体或生成清单。

相同参考事件可以因不同系统进入多个槽。以 `(sequence, gate_id, reference_id, target_frame, direction)` 为展示去重键：抽样完成后相同键只展示一次，保留所有槽和系统来源；不为被合并的展示槽再抽一个。若与概率抽检/反向清单重复，也只独立核验一次，复用同一人的原始回答，保留其不同入选路径。这样避免人第二次见到同一事件后不再独立，且不会超出120条上限。

U清单是定向诊断清单。即使槽内用了随机数，也不能把它称为全资源随机样本，不能据其比例推断“总体标签错误率”“某系统U的可解决比例”或未抽样U的机制构成。仅列槽母体量、抽到键、重复关系、已核验/不确定/未核验状态。概率抽检的设计权重和分母仍按其自身原始清单计算，不因去重展示或U身份改变。

## 3. 核验页面与判定边界

所有条目在同一页面格式、同一任务措辞下混合随机呈现；沿用v1两人的独立顺序种子20261028/20261029。页面不显示U代码、系统名称、检测框、轨迹、算法分数、配对、报警、层号、抽样来源、另一人的答案或预期结果。视频只叠加冻结几何；第一遍后可打开来自原参考的“待核目标”提示，操作记录沿用v1。参考框也不是正确性保证。

两人只回答v1的视觉问题：参考目标是否穿越、方向、两侧是否同一人、可支持的时间区间与证据帧。U条目额外记录“仅凭展示的原图是否足以支持两侧身份”，但不得让人猜是哪个算法步骤出错。扩展观看仍限v1的±5秒、60秒单条预算；更长上下文才可判断的，保留证据不足。

页面生成前检查固定目标种子帧是否存在且位于已批准的展示范围。不存在、在范围外或无法形成目标提示时，保留入选条目并记 `reference_target_not_locatable`；不临时挑另一帧，不从系统轨迹补目标，不扩大展示范围。它单列为呈现/参考定位不足，不进入完整视觉核验的一致性分母，也不等同两人看完后仍无法判断身份。若需更长上下文，另行批准并保留原状态和轮次。帧存在但目标本身看不清，则按v1保留视觉不确定，不混成技术失败。

“盲”仅指本次页面不显示系统输出、U类型或另一人的答案，不声称核验人从未接触开发材料。开始前记录两人是否曾看过本项目开发案例、统计或相同片段，仅用于披露，不据此换样本。两份独立提交仍在讨论之前锁定。

**这套盲核验不能直接判定系统轨迹与参考目标是否同人。** 因为页面故意不显示系统输出，它只能检查E1依赖的参考事件与可见身份支持。即使人类确认参考目标过线，也不能自动把 `U_IDENTITY` 改成检测缺失或串人；即使仍无法看清，也不能当成GT错误。需要显示系统框才能解决的对应问题必须另设审核阶段、单独授权，且不能与这次盲标签核验合并计算一致性。

两人相同的“不确定”不是通过。未知率、技术失败、未完整观看、超时和未核验分别报告；不删除难例。两人的原始提交先锁定，再允许分歧讨论；AI不能充当任何一名核验人。

## 4. 计时、结果与执行门槛

仍沿用v1每人180分钟分配：说明及合成练习15，独立阶段120，提交检查10，分歧处理20，缓冲15（**估计，未实测**）。每条60秒内提交，未完成按v1记状态，不能挪用裁决时间掩盖超时。样本上限并不保证两人能看清或完成全部条目。

新增定向U表独立于概率质量表，逐项给参考支持/反对/不确定、身份支持、时刻区间、支持帧和未完成原因。方向/身份的混淆表、原始一致率、κ等仍用v1规则并列分母；最多12条不适合给稳定的系统间比较。不得用本定向表回填E1既有自动类别，后续人工修订必须另存版本并重建依赖结果。

本增补没有落实第二核验人，没有渲染许可，也没有扩大测试读取范围。执行前仍需：Claude批准基础文本及本增补的完整哈希；冻结许可范围/母体/抽样脚本/页面；用户落实第二人和时间；测试与外部序列另行授权。未满足就记录未执行。10/27、11/6质量关口不变。

`DOCUMENTS_READY`不等于`SAMPLING_READY`：后者还要求各母体的完整清单、哈希、区间语义、字段映射和可显示范围。`CONFIRMATION_READY`另须明确主标签视图，以及unknown/ignore/争议/未核验的分子分母处理和原始视图敏感性。缺件保持`NOT_EXECUTED`，不得由实现自行采用默认值。
